SIGNATUREFLOW 2.0.1 — CONNEXION ET PUBLICATION VÉRIFIÉE

Télécharger SIGNATUREFLOW-V2.0.1-TERMUX.zip dans Téléchargements, puis coller :

termux-setup-storage
pkg install -y unzip
SF_STAGE="$(mktemp -d "$HOME/signatureflow-v2.XXXXXX")"
unzip -q "$HOME/storage/downloads/SIGNATUREFLOW-V2.0.1-TERMUX.zip" -d "$SF_STAGE" &&
bash "$SF_STAGE/signatureflow-main/update-termux.sh"

Attendre le message SUCCÈS avec la version 2.0.1 et le lien à ouvrir.
La commande signale un échec et donne le journal GitHub si la publication échoue.
Après une erreur de déploiement, relancer seulement :
cd "$HOME/signatureflow" && bash deploy-and-verify.sh

Par défaut : dépôt GitHub signatureflow, dossier ~/signatureflow.
Pour un autre emplacement :
SIGNATUREFLOW_REPO_DIR="$HOME/mon-dossier" bash "$SF_STAGE/signatureflow-main/update-termux.sh" Proprietaire/Depot

Si les secrets ne sont pas encore renseignés :
cd ~/signatureflow
bash configure-and-deploy.sh

Suivi :
gh run list --workflow supabase.yml
gh run list --workflow pages.yml

L’application est reconstruite et publiée après le succès du backend.
Aucun destinataire n’est contacté par ces commandes.
Le service e-mail Resend est facultatif : les liens peuvent être copiés et envoyés par JDC ou votre messagerie.
Lire README.md pour le premier déploiement et les limites de l’analyse.
